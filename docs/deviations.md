# Deviations, withdrawn claims and additions after the plan

Hand-written; not covered by `make check`. The numbers behind this list are in the generated block at the end of the README.

- **Data source.** The first commit (README, `config.py`, `data/provenance.json` and its message) said that the CFPB had removed narratives from the live database in a named API release and that the narratives came from a byte-identical mirror of the official bulk export. Neither statement could be verified and both were withdrawn later the same night (the wording in `config.py` and `provenance.json` changed with the commit that added the analysis code). What is verified: product, issue, company and recorded response of every complaint against the live API. The narrative text matches nothing official; it is used because no official source of narratives was reachable, and the copy is pinned by its hash.
- **Before the plan.** The classic baseline had already been scored on DEV when the plan was committed (the first commit's `config.py` cites a DEV learning curve, and wrongly calls it flat).
- **Baseline grid.** The first commit searched four values of C without class weighting; the plan text asks for class weighting, and the grid was widened to match it after the first commit. This raised the baseline.
- **Baselines in the headline.** An earlier version of this README left the planned company rule out of the first table and showed a keyword rule added after DEV results instead. Both are shown now, with two issuer analyses added after an independent review (a separate AI-agent session given a reviewer role, not a person; `docs/analysis_plan_human_labels.md`, Amendment 1, uses the same words for the same kind of review).
- **Judge v2** does not do what plan item six says: it does not address the largest category of disagreements (a prior denial by the issuer), and it changes the question from deciding to predicting.
- **Error reading.** The plan says every disagreement is read and categorised. The categories were drafted by an AI coding assistant working on this repository, in minutes; an earlier README said "a single reader". The figure "most disagreements are not decidable from the text" from that version is withdrawn. The registered human-label plan (`docs/analysis_plan_human_labels.md`, section "Why") gave that figure as its motive; it is now marked there as withdrawn, and the rest of that plan is unchanged.
- **Freeze file.** Plan item four names `results/test_run.json`; the frozen method is in `results/frozen.json`, and `test_run.json` is only the marker of the run. A first freeze covered fewer files and one decision rule; it was replaced before any held-out call. A dry run of the held-out command printed that the input filter changes no held-out complaint; nothing was changed in response, and the dry run no longer touches held-out text.
- **Controls** were added to the gaming test (a neutral sentence, and the same narrative sent again) after a concurrency check showed that the model does not repeat itself; the five rewrites are unchanged.
- **Added after DEV results were seen**, none changing a planned metric or the operating rule: the test-retest replay, the registered noise pass over the held-out split, AUC and the within-issuer comparison, the reading of the operating point as three outcomes, the date-half table, the split-half checks, and the blind human labels (plan in `docs/analysis_plan_human_labels.md`).
- No acceptance rule for v2 existed before v1 and v2 were compared on DEV; one is frozen for the held-out comparison, where v1 is run as well. The fact model's regularisation was left at the library default. The logistic regression is fitted in double precision because with the defaults its result depended on the order of the training rows; its DEV result did not change.
- **After the held-out run, presentation only (first change).** The README was reorganised so that the held-out result comes first; the wide DEV table, the disagreement reading, the gaming test, the automation analysis and the full held-out tables moved from it to `results/report.md`, where the same generated sections already were. `src/judge/report.py`, one of the files hashed in `results/frozen.json`, gained the blocks of the first screen and of the practitioner section, a shorter list of blocks the README must contain, post-run wording for the DEV lead in the full report, and a check that accepts a change to that one file only while `results/post_run_changes.json` records its hash at the freeze and its hash now; a change to any other frozen file still fails `make check`. The report was regenerated before and after the change: every value in `results/metrics.json` is unchanged (the only addition is that record), and every section of `results/report.md` that existed before is unchanged apart from the opening words of the DEV lead and that record. The frozen file, the run marker and the caches were not touched and the method was not re-frozen. Commit: `dac4cfbeb45a`.
- **After the held-out run, second change (2026-11-10, after four reviews by separate AI-agent sessions given the roles of an evaluation engineer, a hiring manager, an operations lead and a security reviewer).** No frozen number was recomputed differently and the method was not re-frozen. What changed:
  - The README's first screen now gives plain agreement figures, the error direction of each system and the issuer finding; the claims list separates the two frozen items that cannot fail; the person's figures will never sit in a DEV column (the labelling sample is drawn from TRAIN); the practitioner section is marked exploratory throughout.
  - Sentences the reviews showed to be false or overstated were corrected: "only the prompt that predicts the record is moved by these rewrites" (the fake note turned all of judge v1's denials into relief; the test had no power for v1); the filter's catch rate without its misses on other wordings; "the issuer explains the record at least as well as the text" (the paired difference cannot tell them apart); "DEV and held-out disagree" on judge v2 (the change is within sampling variation); "every number is checked" (only the generated blocks are; the README now says what the check covers); the within-issuer statement (one lower bound sits at the edge); "the commit is to be published before the run" (it was not; its hash was written to a gist before the run).
  - The settings table says that AUC intervals use 2,000 resamples, which is what the frozen code computes; the frozen `bootstrap_b` of 10,000 applies to kappa, accuracy, paired differences and coverage. No interval was recomputed in place.
  - The estimates table names its interval method and gives the Wilson interval beside the percentile one.
  - New, exploratory, in `src/judge/posthoc.py`: accuracy against always answering no relief; the paired kappa difference between TF-IDF and the issuer lookup; the six frozen judge-against-baseline intervals at the Bonferroni level; DEV against held-out as two independent samples; judge v2's within-issuer interval with 10,000 resamples; the TF-IDF automation slice against the issuer lookup; a gaming test of the TF-IDF model on DEV; further wordings and harmless sentences against the input filter; what the fake note changed in the extracted facts; a Holm correction of the gaming tests; relief by sub-issue; a check of the answer files at the run commit and of the hashes in the gist.
  - The presentation code moved from `src/judge/report.py` to the new `src/judge/frontpage.py`; the human-label sections were rewritten to the layout described in the README. The labelling tool, its sample and its translations were not touched, and no label was read.
  - `results/post_run_changes.json` records every changed or added file with its hash at the freeze (null for a file that did not exist) and its hash now; `make check` accepts a difference from the frozen method only for those files. `results/metrics.json` changed only by the added `posthoc` key and in the list of post-run change records; every other value it held before is unchanged (compared leaf by leaf).
  - The human-label plan was not amended: when this change was made, a label file already existed (it was not opened). The plan does not register the issuer lookup on the labelled sample or the direction of disagreement; both are printed, marked as not registered.
- **Labelling aid.** The Russian rubric (`docs/labelling_rubric_ru.md`), the Russian button labels and the translations exist because the annotator reads English at an intermediate level; the English original is always shown and is what counts. Before Amendment 1 the judged model itself translated an earlier labelling sample; those translations were discarded without being shown to the annotator, and those calls are not in the call counts of the cost table (the full report gives their number).
